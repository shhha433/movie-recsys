# 双塔召回 + DIN 排序的推荐系统

## 项目简介

在 MovieLens-1M 上实现一条完整的**两阶段推荐链路**：双塔模型从全库召回 top-50，
DIN 对这 50 个候选重新排序。整条链路可以一键复现，并且用**端到端指标**而不是"模型各自的 AUC"来评估。

**主要结果**：

| 环节 | 指标（口径） | 结果 | 随机基线 |
| --- | --- | --- | --- |
| 召回 | test AUC（1 正 + 4 随机负） | **0.8904** | 0.50 |
| 召回 | Recall@50（全库 3883 选 50） | **15.19%** | 1.29%（约 11.8 倍） |
| 排序 | DIN test AUC（1 正 + 4 随机负） | **0.8024** | 0.50 |
| **端到端** | **HR@10（召回 top-50 → DIN 重排）** | **6.30%** | 0.26%（约 24 倍） |

三层口径不同，不能横向比较——只有**端到端**那一行是"线上会看到的数"。
排序层把召回命中的 15.19% 兑现成 6.30%，**兑现率 41.5%**；直接用召回分数只有 21.1%。

与同数据、同 mask 池化、同随机种子的无 genres 双塔相比：
Recall@50 从 **12.12% 提升到 15.19%**（+3.07pp，配对 bootstrap p<0.001），
端到端 HR@10 从 **5.49% 提升到 6.30%**。

> 2026-11-10 已修复难负样本中的 chunk 下标错误，并改为排除用户此前喜欢过的全部物品。
> 两组修正后 hard 数据均为 1,819,384 个负样本，target/history/此前喜欢物品泄漏均为 0；
> 下文 DIN 与端到端指标均来自修正后重训。

## 一、数据集

| 项目 | 说明 |
| --- | --- |
| 名称 | MovieLens-1M（GroupLens / 明尼苏达大学） |
| 来源 | https://grouplens.org/datasets/movielens/1m/ |
| 内容 | 6040 位真实用户、3883 部电影、100 万条真实评分（2000–2003 年） |
| 正样本定义 | 评分 ≥ 4 视为"喜欢" |
| 切分方式 | **按时间切分**：前 80% 训练 / 中 10% 验证 / 后 10% 测试 |

**为什么按时间切分**：随机切分会让模型在训练时"看到未来"，离线指标虚高、上线就崩。

### 样本构造

把每位用户的观影序列滑窗成 `(历史, 目标, 标签)` 三元组：

```text
序列：[M1, M2, M3, M4, ...]
   历史 "M1"          → 目标 M2    label 1
   历史 "M1"          → 目标 M77   label 0（随机负样本）
   历史 "M1 M2 ..."   → 目标 M3    label 1
   ...
```

- **历史保留最近 20 个物品**，左补 0 补齐到 20 列
- 正负样本 1 : 4
- 最终训练样本 **2,274,230 条**

## 二、整体架构（6 步流水线）

```text
prepare_data.py          原始评分 → train/valid/test.csv
        ↓
two_tower.py             训练召回模型 → 向量 + model_two_tower.pt
        ↓
recall_eval.py           Faiss/向量检索 → Recall@50
        ↓
build_hard_negatives.py  用召回 top-50 挖难负样本 → train_hard.csv
        ↓
din.py                   训练排序模型（吃 train_hard.csv）→ model_din.pt
        ↓
rank_eval.py             召回 top-50 → 排序重排 → HR@10 / NDCG@10 / MRR
```

全部可以 `./run_all.sh` 一键跑完。

**为什么必须分两个阶段**：双塔的用户向量必须与候选无关，才能离线预计算、建索引、用 ANN 检索；
而排序层的候选是输入的一部分，用户表示可以随候选变化。两层能做的事不同，代价也不同。

## 三、召回层：双塔模型

```text
历史序列 [B, 20] → 物品表示 → mask 平均池化 → MLP → 用户向量 [B, 32]
                                                        ↘ 内积 → 分数
候选物品 [B]    → 物品表示 →        MLP → 物品向量 [B, 32]

物品表示 = ID Embedding + Linear(18 维 genres 多热向量)
```

**关键设计点**：

1. **两塔共用同一张物品 Embedding 表**——历史和候选是同一批物品
2. **`padding_idx=0`**：第 0 行恒为 0 且不参与训练，mask 平均池化排除 padding
3. **用户塔看不到候选**——这是双塔的定义，否则用户向量无法离线预计算
4. **训练 10 轮**：3 轮时 valid AUC 还在每轮 +0.01 上涨，明显欠拟合
5. **genres 是共享侧特征**：历史物品和候选物品都使用同一个 `_item_vec()`，不会只加到一侧

## 四、排序层：DIN

### 4.1 为什么召回层不能用注意力

用户塔算用户向量时**看不到候选物品**——这是双塔能离线预计算的前提。
所以召回层只能用「与候选无关」的池化：平均、最近 N 个、时间衰减。

排序层候选是输入之一，用户表示可以随候选变化——DIN 的注意力就建立在这个自由度上：
**要猜他喜不喜欢这部科幻片，就重点看他看过的科幻片。**

### 4.2 注意力怎么算

1. 历史向量 `h ∈ [B, L, d]`，候选向量 `q ∈ [B, d]`
2. 打分网络（两层 MLP）吃三段拼接 `[候选, 历史, 候选 − 历史]` → 每个历史位置的分数 `[B, L]`
3. padding 位置先置 `-inf` 再 softmax → 权重；用它加权求和 `h`

**两个坑**：mask 必须在 softmax **之前**（否则剩余权重和不再是 1）；
`padding_idx=0` 让 padding 的 `h` 是零向量，不 mask 会把真实位置的权重和压到小于 1。
`din.py` 带训练前不变量检查，不通过就不进训练。

### 4.3 难负样本：这一步决定了排序层有没有用

排序层如果只用全库随机负样本训练，会遇到 **train-serving skew**：训练时负样本跟正样本差得远，
推理时面对的却是召回出来的相似候选，模型没学过怎么在"鸡蛋里挑骨头"。

`build_hard_negatives.py` 用召回 top-50 挖负样本，但有一条关键规则：

> **只在目标物品被召回时才用召回候选当负样本，其余退回随机负样本。**

因为目标没被召回时，top-50 全是"召回模型认为用户会喜欢的物品"。把它们当负样本，
等于教模型"召回候选 = 负"——实测这样训出来的模型 AUC 从 0.85 崩到 0.53，端到端还不如不排序。

无论使用哪种来源，负样本都必须排除用户历史上所有评分 >=4 的物品和当前目标；
随机兜底从全库候选索引中抽取，保证与排序阶段的候选分布一致。

当前 genres 模型的验证集 Recall@50 为 15.19%，因此端到端评估中共有
8,573 / 56,440 个验证目标进入了候选池。

## 五、评估方式

| 指标 | 怎么算 | 用在哪 |
| --- | --- | --- |
| **AUC** | 1 正 + 4 随机负上的排序质量 | 召回层、排序层 |
| **Recall@50** | 全库 3883 里检索 top-50，看目标是否命中 | 只有召回层 |
| **HR@10** | 目标是否进了前 10（0/1 平均） | 端到端 |
| **NDCG@10** | 目标排第 r 名得 `1/log₂(r+1)`，越靠前越高 | 端到端 |
| **MRR** | 目标排第 r 名得 `1/r` | 端到端 |

**HR / NDCG / MRR 的区别**：HR 只看"进没进前十"；NDCG 关心位置但用对数衰减（前 3 名权重高）；
MRR 衰减最陡（第一名满分、第二名砍半）。首页只有 10 个位置，**NDCG 最接近真实业务价值**。

**两种口径**：
- **端到端**：分母是全部 56,440 个验证用户，目标没被召回的记 0 分 → 模拟线上
- **条件口径**：只看被召回的样本 → 衡量排序层本身的强弱
- 关系：`条件口径 = 端到端 ÷ Recall@50`

**训练用的 loss 和这些指标是两回事**：双塔和 DIN 都用 `BCEWithLogitsLoss`，只在训练集上算，
是唯一的训练信号；AUC / Recall / HR 不参与参数更新。

## 六、实验结果

### 6.1 召回层：无 genres vs 有 genres

固定数据、历史长度 20、mask 池化、10 轮训练和随机种子 42，只改变是否加入 genres。

| 实验 | test AUC | Recall@50 | 命中 / 总数 | 95% CI |
| --- | --- | --- | --- | --- |
| 无 genres | 0.8812 | 12.12% | 6,840 / 56,440 | [11.86%, 12.42%] |
| **有 genres** | **0.8904** | **15.19%** | **8,573 / 56,440** | **[14.92%, 15.50%]** |

配对 bootstrap：

| 指标 | 结果 |
| --- | --- |
| Recall@50 差值 | **+3.07pp** |
| 差值 95% CI | [2.80pp, 3.37pp] |
| p 值 | **<0.001** |

模型参数从 128,512 增加到 129,088，仅增加一个 `18 × 32` 的 genre 投影。

### 6.2 历史召回消融

以下结果来自加入 genres 前的历史实验，用于说明池化和相似度的选择：

| 实验 | 改动 | Recall@50 | vs baseline | p 值 | 结论 |
| --- | --- | --- | --- | --- | --- |
| baseline | 平均池化 + 内积 | 12.10% | — | — | 历史起点 |
| A | 池化改成「取最近一个」 | 7.06% | −5.04pp | <0.001 | 显著变差 |
| B | 训练时向量归一化（余弦） | 7.59% | −4.51pp | <0.001 | 显著变差 |
| C | 池化改写成 masked mean | 12.19% | +0.09pp | 0.118 | 不显著，与 mean 等价 |

早期历史 3 条、训练 3 轮时，余弦曾显著更好；数据与训练充分程度变化后结论反转。
这说明归一化收益依赖实验条件，不能把小规模结论直接推广。

### 6.3 排序层

最终 genres 召回使用对应的条件难负样本重新训练 DIN：

| 指标 | 无 genres 召回 | genres 召回 |
| --- | --- | --- |
| DIN valid AUC | 0.8507 | 0.8425 |
| DIN test AUC | 0.8108 | 0.8024 |

DIN 的随机负 AUC 略低不等于端到端退步。两份 DIN 面对的难负样本候选分布不同，
排序层的真实价值必须看 6.4 的候选内重排。

### 6.4 端到端：召回 top-50 → DIN 重排

| 召回模型 | 排序方式 | HR@10 | NDCG@10 | MRR |
| --- | --- | --- | --- | --- |
| 无 genres | 直接用召回分数 | 0.0246 | 0.0107 | 0.0105 |
| 无 genres | DIN 重排 | 0.0549 | 0.0271 | 0.0223 |
| **genres** | 直接用召回分数 | 0.0320 | 0.0142 | 0.0139 |
| **genres** | **DIN 重排** | **0.0630** | **0.0299** | **0.0247** |

最终 genres 链路中，DIN 相比“直接用召回分数”提升：
HR@10 **+3.10pp**、NDCG@10 **+1.57pp**、MRR **+1.08pp**。

条件口径（只看被召回的 8,573 个样本）：

| 排序方式 | HR@10 | NDCG@10 | MRR |
| --- | --- | --- | --- |
| 直接用召回分数 | 0.2108 | 0.0937 | 0.0912 |
| **DIN 重排** | **0.4148** | 0.1968 | 0.1623 |

genres 的主要收益来自**扩大召回覆盖**：被召回目标从 6,840 增至 8,573。
条件口径下，无 genres 的 DIN HR@10 为 45.29%，genres 的 DIN HR@10 为 41.48%。
因此 genres 的端到端提升主要来自召回覆盖增加，同时 genres 对应的条件难负样本也明显更难。

### 6.5 结论

1. 在固定 mask 池化和相同训练配置下，加入 18 类 genres 使 Recall@50 从 12.12% 提升到 15.19%，配对 bootstrap 证明差异显著。
2. 端到端 HR@10 从 5.49% 提升到 6.30%，增益主要来自召回覆盖，而不是 DIN 条件兑现率提升。
3. genres 链路中 DIN 在真实候选池内条件 HR@10 为 41.5%，说明更难候选会压低条件排序指标。
4. 难负样本只能在目标确实被召回时使用；错误地把所有 top-50 都当负样本会使模型学反，AUC 曾从约 0.85 崩到 0.53。
5. AUC 与 Recall@50、HR@10 的口径不同，不能用一个指标代替完整链路。

### 6.6 决策记录

| 决策 | 备选方案 | 我做了什么 | 结果 | 单变量？ | 最终选择 |
| --- | --- | --- | --- | --- | --- |
| genres 特征 | 开 / 关 | 固定 mask、seed=42、10 轮，两组重训并做配对 bootstrap | Recall@50：12.12% / **15.19%**；HR@10：5.49% / **6.30%** | ✅ | **开** |
| 召回池化 | 平均 / 取最后一个 / mask | 同数据训练 + 配对 bootstrap | 12.10% / 7.06% / 12.19% | ✅ | **mask**（与 mean 等价） |
| 相似度 | 内积 / 余弦 | 两组训练 + 配对 bootstrap | 12.10% / 7.59% | ✅ | **内积** |
| 历史长度 | 3 / 20 | 全链路重建 | 6.76% / 12.10% | ❌ 同时改了训练轮数 | **20** |
| 训练轮数 | 3 / 10 | 观察 valid AUC | 3 轮时仍在上升 | ❌ | **10** |
| 排序层 | 直接召回排序 / DIN | 候选内重排 | HR@10：3.20% / **6.30%** | ✅ | **DIN** |
| 排序负样本 | 全库随机 / 条件难负 | 目标召回时用难负，否则随机兜底 | 端到端从输给召回排序变为显著提升 | ✅ | **条件难负** |

> 历史长度 3/20 条与训练轮数 3/10 轮是在同一次重建中一起调整的，
> 不能把全部提升单独归因给其中一项。

## 八、如何运行

```bash
# 0. 下载 MovieLens-1M 解压到 data/ml-1m/

# 一键运行 genres 最终链路
./run_all.sh

# 运行无 genres 对照组并指定独立目录
python two_tower.py \
  --pooling mask --no-genres \
  --out-dir emb_mask_nogenre --epochs 10 --seed 42

# 运行 genres 组
python two_tower.py \
  --pooling mask --genres \
  --out-dir emb_mask_genre --epochs 10 --seed 42

# 只比较这两组
python recall_eval.py \
  --experiments emb_mask_nogenre emb_mask_genre \
  --baseline emb_mask_nogenre

# 使用指定召回模型生成难负样本、训练 DIN、做端到端评估
python build_hard_negatives.py \
  --ckpt emb_mask_genre/model_two_tower.pt \
  --out data/processed/train_hard_emb_mask_genre.csv
python din.py \
  --train-split train_hard_emb_mask_genre \
  --ckpt-out emb_mask_genre/model_din.pt
python rank_eval.py \
  --emb-dir emb_mask_genre \
  --ckpt emb_mask_genre/model_din.pt
```

## 九、实现中的坑

**PyTorch 和 faiss-cpu 在 macOS 上不能同进程**：两者各带一份 OpenMP，先后使用会静默崩溃
（退出码 134/139、无 Python 报错）。实测 `faiss.omp_set_num_threads(1)` 和
`KMP_DUPLICATE_LIB_OK=TRUE` 都无效。方案是训练与检索拆进程——这也正是工业界
离线训练 / 在线检索分离的架构。`rank_eval.py` 因此用 numpy 暴力检索（3883 个物品只要 2 秒），
不 import faiss。

## 十、已知局限

- genres 使用简单多热编码，没有编码类目之间的语义关系；标题、演员、导演等特征仍未使用。
- 目前只有一份时间切分和单一种子完成最终对照，尚未通过多时间窗口、多种子验证泛化稳定性。
- Recall@50 的差异已做配对 bootstrap，但 HR@10、NDCG@10 的端到端差异尚未单独做显著性检验。
- 召回率虽提升到 15.19%，仍有约 85% 的验证目标未进入 top-50 候选池，召回覆盖仍是主要瓶颈。
- genres 的端到端增益主要来自召回覆盖增加；带 genres 的候选更难，DIN 条件口径 HR@10 为 41.48%，
  低于无 genres 的 45.29%，说明排序层仍适配优化。
- 未针对冷启动物品单独统计指标，因此不能仅凭整体提升推断 genres 一定改善冷启动。
- 负采样仍是随机负样本与条件难负样本的简单组合，没有做 popularity 去偏。
- 排序层采用内积打分，与原 DIN 的「用户兴趣向量与候选向量拼接后过 MLP」仍有差别。
- 未做系统超参数搜索，`EMB_DIM`、学习率和训练轮数均采用经验配置。

## 十一、后续计划
